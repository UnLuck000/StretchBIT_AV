# Исправления аудита после 1.2.2

## Автоматические действия и YARA

- `Webshell_in_image` переведено в `confirm`: PNG с учебным PHP-текстом в tEXt
  не считается достаточным основанием для автокарантина.
- `weak + confirm`, `эвристика + confirm` и слабое правило на файле с отозванной
  подписью остаются неразрушающими находками. Сильное правило/вредоносный хэш
  по-прежнему может разрешить автоматическое действие.
- Результат сканирования несёт SHA-256. Перед автодействием файл открыт без
  разрешения записи/переименования, копия сверяется с ожидаемым хэшем, угроза
  повторно проверяется по этому открытому объекту. Лишь затем вызывается
  завершение процесса, удаление — по тому же Windows HANDLE, не по пути.
- Ошибка проверки/блокировки не даёт разрешения завершить процесс или удалить
  изменившийся файл. Карантин отменяется, находка остаётся для разбора.
- Для системного запрета проверяется также конечный путь открытого объекта.

Правила сообщества не исправляются на диске: обновление баз перезаписало бы
такие изменения. Политика находится в движке и release_overrides.json.
Неактивные записи confirm оставлены как предосторожность при возврате upstream-правил,
но их примечания исправлены. Полный clean-corpus аудит не подменяется этими тестами.

## Разделение пользователей

Пользовательские записи журнала дедуплицируются с учётом SID; ручной карантин службы
сохраняет SID клиента. Обычный клиент читает/изменяет только свой карантин и изменяет
только свои записи. При чтении журнала также доступны явно машинные события защиты.
Карантин автоматической защиты и старые записи карантина без владельца доступны
только администратору. Старые записи журнала без SID и без явно заданной машинной
области не считаются автоматически общими.

Ограничение установлено сервером, а не только фильтром интерфейса. Поля SID от
клиента не принимаются. Перед восстановлением проверка выполняется до записи в
переданный файл назначения.

## Загрузка и обновления

- Общий транспорт public_http.py проверяет начальный URL и редиректы; DNS
  разрешается при соединении один раз, connect получает проверенный числовой IP.
  IPv4-mapped IPv6/сокращённые IPv4 и локальные сети не обходят контроль.
  Прокси из окружения выключены; TLS-проверка сертификата и имени сохранена.
- Подписи Ed25519 отклоняют S >= L, неканонические точки, точки вне кривой и
  точки вне главной ненулевой подгруппы. Ключи подписи имеют строго 32 байта.
  Реализация остаётся локальной Python-реализацией, не новой внешней библиотекой.
- Зеркало не принимается без закреплённого публичного ключа. Сборщик не публикует
  неподписанные данные; перед переиспользованием прежний манифест проверяется
  ключом, а файлы — по безопасному имени и SHA-256.
- VirusShare сохраняет прежние записи при сбое определения номера, использует
  зеркало при сбое GET отдельного списка и сообщает частичный результат.
  Расширение `.md5.gz` теперь проходит проверку безопасного имени.

**Перед выпуском требуется настройка владельцем репозитория:
[FEEDS_SIGNING.md](../operations/FEEDS_SIGNING.md).**
Ключи не генерировались, Secrets GitHub не менялись. До закрепления ключа клиент
отклоняет зеркало, а прямые источники используются по прежним правилам.
Подпись не изолирует ключ от доверенного workflow CI.

## Остальное

- Отсутствие времени загрузки профиля больше не исключает его из мониторинга.
- Настройка автозапуска GUI отделена от наличия задания восстановления сети.
  При ошибке задания настройка откатывается; установщик создаёт лёгкое задание
  и без выбранного автозапуска GUI.
- manifest.json присланного ZIP ограничен до распаковки/JSON-разбора.
- Версия обновления отмечается показанной только после открытия changelog;
  предложение в трее не теряется после перезапуска GUI.
- Исправлен завершающий перевод строки appinfo.py.

Тесты используют временные файлы и подставные сетевые ответы. Рабочие службы,
реальные загрузки, установщик и завершение настоящих процессов не запускались.
