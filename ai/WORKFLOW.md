# Правила работы с проектом

- Windows, Python 3.12, PySide6. Ответы, интерфейс и комментарии — по-русски.
- Проверить git status, не перезаписывать чужие изменения. Коммиты выполняет пользователь.
- Минимальные изменения; сначала прочитать локальную память OPENCODE.md в main.
- После правок: `python -m ruff check .`.
- Перед полным pytest: `tasklist | findstr /i "StretchBIT"`. Не завершать процессы
  без разрешения. Если программа работает, предупредить о возможной остановке тестов.
- Тесты: `python -m pytest tests -q --basetemp="<уникальная временная папка>"`.
- Не запускать реальные загрузки, установщик, системные операции и тяжёлые проверки
  без согласования. В тестах использовать временные файлы и подставную сеть.
- Не публиковать закрытые ключи. GitHub Secrets не менять без отдельного согласования.
- Автокарантин разрешается только подтверждённой сильной находке/вредоносному хэшу.
  Утилиты, расширения и уязвимые драйверы сами по себе не основание автодействия.
- Не называть YARA-правило безошибочным по одному чтению условия. Статический аудит,
  компиляция, синтетический контрпример и clean-corpus проверка — разные уровни доказательств.

## Обновление базы

Документы в этой ветке сохраняются отдельным коммитом пользователя.
Переносить только справочную информацию, а не весь main. Помечать дату и исходный
коммит. Изменения программы идут в main, EULA и лицензии зависимостей остаются там.
