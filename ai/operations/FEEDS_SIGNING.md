# Подпись зеркала баз

Клиент отказывается от зеркала без `updater.FEEDS_PUBLIC_KEY`. Прямые источники
работают как раньше, а источники abuse.ch напрямую требуют пользовательский API-ключ.
Пустой публичный ключ — блокер публикации релиза с рабочим зеркалом, не режим доверия.

Настройка выполняется владельцем репозитория:

1. Локально запустить `python tools/feeds_keygen.py`. Не отправлять вывод в чат/лог CI.
2. Закрытый ключ записать в GitHub Actions secret `FEEDS_SIGN_KEY`, не в Git.
3. Публичный ключ закрепить в `updater.FEEDS_PUBLIC_KEY` и пересобрать приложение.
4. Запустить «Зеркало баз» и проверить обновление клиентом с закреплённым ключом.

Неподписанный или подписанный другим ключом предыдущий манифест не используется
для повторного подписания старых данных. При первой настройке/смене ключа источники
будут загружены заново. Файлы проверяются по SHA-256 и безопасному имени.
Отсутствие/ошибка закрытого ключа останавливает публикацию, unsigned fallback нет.

Граница доверия: workflow, исполняемый код и администраторы GitHub Secrets имеют
доступ к закрытому ключу. Подпись защищает клиента от подмены данных ветки feeds
без ключа, но не от компрометации доверенного workflow или ключа.
Для изоляции от CI нужна отдельная служба подписания вне этого workflow.
