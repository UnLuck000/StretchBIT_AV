StretchBIT — учебный антивирусный мультитул для школьного проекта.
Он не является сертифицированным антивирусом и не гарантирует обнаружение всех угроз.

Создан на базе языков программирования Python и C++

В ZIP соглашение показывается при первом запуске и при изменении его редакции.
После интерактивной установки повторное ознакомление с теми же документами
не требуется для установившего пользователя. При тихой установке и для других
пользователей документы показываются при первом запуске.
Сервиса отправки логов пока нет: кнопки отправки отключены, отчёт можно сохранить
только локально. Дополнительная диагностика и логи VPN требуют отдельных согласий.

Главное окно и автозапуск работают в контексте запустившего пользователя, без
общего запроса UAC. Системная защита и привилегированные VPN-подключения выполняются
службой, отдельные системные инструменты могут запрашивать повышение прав.
Установка регистрирует вход для всех пользователей, а не только для установившего
администратора. Личный выбор автозапуска имеет приоритет над исходным выбором мастера.
Конфигурация и VPN-профили создаются отдельно для каждого пользователя; пути Windows
получаются для текущего токена через Known Folders, а не из окружения администратора.
Обычное открытие инструментов не требует UAC. Для дополнительных прав есть отдельная
кнопка/меню, а создание точек восстановления и SFC/DISM запрашивают права при действии.
TUN, WireGuard и OpenVPN из обычного GUI требуют доступного привилегированного ядра; его отсутствие
не приводит к повышению всего окна или записи VPN-конфигурации в профиль администратора.
Новые пользовательские профили подхватываются работающим ядром периодически
и при подключении GUI, без необходимости входить под администратором.
Привилегированный launcher разрешается отдельной включённой по умолчанию галочкой
установщика. Это явное делегирование пользователям доступа к известным системным
инструментам от SYSTEM, с широкими возможностями изменения компьютера. Администратор
может отказаться от него при установке. У старой установки разрешение не появляется
само от обновления пользовательских настроек.

В настройках можно отдельно выключить использование launcher для своего GUI:
тогда доступные без прав возможности остаются, а полный доступ запрашивается через UAC.
Личная галочка не выдаёт и не отменяет машинное разрешение администратора.
Отключение относится к новым запускам: уже открытые окна с системными правами
сохраняют их до закрытия; выполняющиеся операции принудительно не завершаются.
При включённом разрешённом launcher обычный запуск и автозапуск используют один и тот же
координатор привилегированного ядра без сохранения пароля администратора. GUI не получает токен SYSTEM.
HKCU системного инструмента привязывается к подтверждённому пользователю сеанса,
а его служебные файлы отделены от личной конфигурации и DPAPI-профилей GUI.

Выбор режима процесса вынесен в `bootstrap.py`, координация привилегированных
инструментов — в `launcher.py`; `gui.py` остаётся совместимой точкой запуска исходников.
ZIP/RAR при первом обычном запуске предлагает перенос в
`Program Files\StretchBIT-archive` (тестовая редакция — `StretchBIT-archive-test`).
После одного подтверждения UAC системный PowerShell проверяет SHA-256 файлов и создаёт
защищённую копию; завершение настройки выполняется только из неё. Затем задача SYSTEM
запускает общее ядро защиты и launcher без регистрации службы SCM и без повторного UAC
для разрешённых инструментов. Подтверждение настройки означает делегирование широких
системных возможностей всем пользователям компьютера, как и разрешение launcher в Installer.
Метаданные `app/install-mode.json` содержат `installed_with_service: true` у Installer
и `false` у архива; это выбор backend, а не разрешение на системные права.
GUI и личные данные остаются у первоначального пользователя даже при вводе другой
учётной записи в UAC. В исходной папке создаётся ярлык. После ответа защищённого ядра
удаляются только неизменённые файлы из списка сборки: неизвестные файлы, изменённые
файлы и метаданные архива сохраняются. Занятые файлы принудительно не удаляются.
Другая копия в целевой папке не перезаписывается; работающая служба Installer не
останавливается автоматически, параллельная защита архивной копии блокируется.
Архив не получает разрешение другой установки.
Служба принимает GUI только своей копии программы; произвольная ZIP-копия не считается
доверенной лишь из-за совпадения имени. Автозапуск SYSTEM из пользовательской папки,
доступной на запись обычному пользователю, не разрешается.
Сборка: `python build_release.py --zip`, необязательно `--rar` и/или `--installer`.
Для настоящего RAR нужен отдельно установленный лицензированный `Rar.exe` из WinRAR.
Сборщик не скачивает WinRAR и не переименовывает ZIP в RAR.
Перенос, UAC и запуск SYSTEM необходимо отдельно проверить на Windows:
автоматические тесты не заменяют установку под двумя разными учётными записями.
Установщик следует запускать обычным открытием: если он заранее запущен
от имени другой учётной записи, Windows/Inno Setup не всегда могут вернуть
контекст первоначального пользователя.
